# Data model

- `ContentId`: validated algorithm-tagged SHA-256 identifier.
- `Patch`: normalized ordered `Add`/`Delete` operations over persistent RDF quads; `PatchId` is its content ID.
- `Commit`: protocol version, zero-to-two ordered parents, patch ID, actor, message, event time, and ledger-controlled recorded time. Parent zero defines reconstruction and `CommitId` hashes canonical bytes.
- `main`: the only mutable ref in the walking skeleton; absence means empty ledger.
- State: a set of canonical N-Quads reconstructed from the parent chain.

Event time is supplied provenance; recorded time is generated by the ledger. Both affect identity, but ancestry—not timestamp order—defines history. Rich provenance requires a later versioned envelope under ADR-0006.
