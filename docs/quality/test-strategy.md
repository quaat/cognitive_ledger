# Test strategy

Unit tests cover IDs, canonical bytes, RDF normalization, ordering, parsing, and error cases. Golden integration tests pin protocol fixtures. The walking-skeleton test covers two commits, historical reconstruction, stale CAS, and reopen persistence. API tests cover health and conflict mapping. Random/property tests must be deterministic or print replayable seeds.

Docker integration (`scripts/test-integration.sh`) runs the real-PostgreSQL store suites (CAS race, shared immutable store, graph authority incl. migration 0007 upgrade, fs→pg migration, atomic workflow) and the authenticated HTTP suite (`crates/ledger-api/tests/pg_api.rs`: auth/authz, tenant isolation, lost-response replay, fail-closed acceptance, limits, safe errors), and the invariant verifier (`pg_verify`: clean history passes, every simulated bypass is detected, verification changes nothing), then drives the containerised server end to end: operator graph provisioning with `ledger-admin`, token-authenticated prepare/accept of v2 candidates under the explicit CI no-validation switch, a container restart, authenticated reads, and SQL verification that only version-2 commits were indexed and every ref move has a ref event; PostgreSQL-backed tests are `#[ignore]`d in the unit gate and never reported as passed when not run; differential tests compare normalized semantic RDF state, never IDs. Qualification harnesses (Plan 0005, not per-commit gates): `scripts/stress.sh` runs `apps/ledger-stress` (≥1,000 concurrent prepare/accept clients against two containerised replicas over one contended graph and over many graphs, every tenth writer duplicating each request to a second replica under one `Idempotency-Key`; latency percentiles, throughput, error classes, runtime-role session utilisation and the SQL invariants — every ref version consumed once, `refs.version = count(ref_events)` = accepted decisions = outbox rows, no deadlock — plus `ledger-admin verify`), and `scripts/fault.sh` runs `ledger-stress fault` under repeated `docker kill -s KILL` of replicas (a fixed count; optionally continuing until a configured number of accepts have been observed as committed-before-the-response-was-lost, which happens only by chance because that window is sub-millisecond — the count is reported; the deterministic proofs are the `test-hooks` pause after `COMMIT` in `pg_lifecycle` for every write path and over HTTP in `pg_api` `p7a_*`, Plan 0013 M1) and of PostgreSQL (replicas must reconnect without being restarted), timed by observed progress and recovered by readiness polling, verifying after each recovery and replaying every in-doubt response verbatim (same key, body and actor) against the database in every quiet window; duplicated-request pairs are only counted as compared when both replicas answered, one-sided admission-control refusals are reported separately, every client-observed landing must exist as a ref event with the same version and head, and any unexpected error class (401/500/`IDEMPOTENCY_CONFLICT`/`DEPENDENCY_TIMEOUT`) fails the run in every mode — stress, branches and fault alike (`fault_unexpected`, since Plan 0013 M1; before, the fault mode let `DEPENDENCY_TIMEOUT` pass) (evidence: [stress](evidence/stress-1000-writers-2026-09-26.md), [fault injection](evidence/fault-injection-2026-09-26.md)); `scripts/backup-restore.sh` (logical dump and base backup under live load, restored and compared: verifier clean, ref chains exact prefixes, states identical through a server on the restore — [evidence](evidence/backup-restore-2026-09-27.md)) and `scripts/upgrade.sh` (previous release built from git, data through its API, documented upgrade order, replay of its idempotency keys, clean-install/upgrade schema convergence — [evidence](evidence/upgrade-2026-09-27.md)). The HTTP suite also proves two in-process replicas over one real JWKS endpoint (rotation, withdrawal, expiry/`nbf` boundaries, replay across replicas and across a key rotation) and the adversarial limits (expensive-operation admission control under a blocked database with `DEPENDENCY_TIMEOUT` for the blocked reads, the edge timeout under a slow database, slow-loris bodies, the exact body-size boundary, pool and RSS health); tests that take table locks run on throwaway databases. Plan 0013 M1 adds the request-lifecycle suites (`crates/ledger-store/tests/pg_lifecycle.rs`, `pg_api` `p7a_*`; [evidence](evidence/plan-0013-m1-lifecycle-2026-10-07.md)): drop before and after `COMMIT` on every write path, abandoned active statements, the backend-reuse cancellation hazard, SQLSTATE mapping through real write transactions, same-key concurrency for non-genesis accept and merge apply, pool exhaustion and heavy-write saturation. Every test is classified PRESERVATION / CHARACTERIZATION / FUTURE ACCEPTANCE / ACCEPTED; `future_*` tests assert a not-yet-implemented ADR-0026 contract, are excluded from suite runs with `--skip future_`, and were run once for their red evidence — a `future_` test is never reported as part of a green suite, no other test name may contain `future_` (the exclusion is a substring filter), and once its behaviour lands the test is promoted into the ordinary suite (renamed, documented ACCEPTED with the red evidence cited), so `test-integration.sh` executes it. Plan 0013 M2 promoted the transaction-bound and outcome-envelope tests and added the validation-record lifecycle, the configuration-hierarchy units, the PostgreSQL 17 backstop through the production pool, the idle-pool borrow, the post-admission ownership and graceful-shutdown tests, and the shared-object wait contract ([evidence](evidence/plan-0013-m2-lifecycle-2026-10-07.md)); only the M3 reserved-headroom test remains `future_`. Fault injection and pause points (`FailPoint`, `PauseHook`, injected slow statements, projector crash windows) compile only with the `test-hooks` feature; `scripts/check-architecture.py` proves no binary's build graph enables it and that the symbols are absent without it. Fuzzing (`fuzz/`, `scripts/fuzz.sh`, bounded in `ci-fuzz`) covers every parser and canonical encoder that consumes untrusted bytes — N-Quads, patch and commit v1/v2 canonical decoders, request bodies and the request-identity encoder, timestamps — with corpora seeded from the golden vectors and fixed-point properties (accepted bytes re-encode identically; reordering never changes an identity) asserted inside the targets. Assertions are not weakened to accommodate defects.
