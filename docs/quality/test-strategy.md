# Test strategy

Unit tests cover IDs, canonical bytes, RDF normalization, ordering, parsing, and error cases. Golden integration tests pin protocol fixtures. The walking-skeleton test covers two commits, historical reconstruction, stale CAS, and reopen persistence. API tests cover health and conflict mapping. Random/property tests must be deterministic or print replayable seeds.

Docker integration (`scripts/test-integration.sh`) runs the real-PostgreSQL store suites (CAS race, shared immutable store, graph authority incl. migration 0007 upgrade, fs→pg migration, atomic workflow) and the authenticated HTTP suite (`crates/ledger-api/tests/pg_api.rs`: auth/authz, tenant isolation, lost-response replay, fail-closed acceptance, limits, safe errors), then drives the containerised server end to end: operator graph provisioning with `ledger-admin`, token-authenticated prepare/accept of v2 candidates under the explicit CI no-validation switch, a container restart, authenticated reads, and SQL verification that only version-2 commits were indexed and every ref move has a ref event; PostgreSQL-backed tests are `#[ignore]`d in the unit gate and never reported as passed when not run; differential tests compare normalized semantic RDF state, never IDs. `stress/` and `fault/` are reserved for explicit later plans. Assertions are not weakened to accommodate defects.
